# HISTORY_IMAGE_STANDARD.md

## Стандарт изображений модуля «Историческая справка»

**Версия:** 1.1  
**Статус:** действует для ручной привязки локальных изображений к событиям History.

---

## 1. Назначение

Зафиксировать правила хранения и привязки изображений к историческим событиям.

Документ описывает только данные и файлы. UI и runtime-логика здесь не определяются.

Документ также задаёт редакционные правила читаемости кадра в закрытой карточке и по-прежнему не определяет UI и runtime.

---

## 2. Поля события

Событие хранится в `history-events-ru.json` внутри `eventsByDate["MM-DD"]`.

### Обязательные поля

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string | Стабильный идентификатор события |
| `title` | string | Короткий заголовок |
| `summary` | string | Краткое описание события |
| `fact` | string | Один интересный факт |
| `sources` | array | Источники подтверждения; как минимум один валидный источник с `title` и `url` |

### Необязательные поля изображения

| Поле | Тип | Описание |
|------|-----|----------|
| `image` | string | Локальный путь к файлу изображения |
| `imageAlt` | string | Текстовое описание изображения для `alt` |
| `imagePosition` | string | Необязательный кадр (`object-position`); формат и fallback — см. `docs/DATA_SCHEMA.md` |

---

## 3. Где хранится `image`

Поле `image` указывается **в самом событии**.

Пример:

```json
{
  "id": "world-1969-apollo11-moon-landing",
  "title": "Первые люди на Луне",
  "summary": "…",
  "fact": "💡 …",
  "image": "assets/history/apollo-11.jpg",
  "imageAlt": "Астронавт Apollo 11 на поверхности Луны",
  "sources": []
}
```

Правила:

- если `image` указан — событие использует этот файл;
- если `image` нет — событие считается без фото (временное допустимое состояние);
- другое событие вместо текущего не подставляется.

---

## 4. Локальные файлы

Все изображения модуля History лежат в каталоге:

```text
assets/history/
```

Путь в поле `image` всегда относительно корня проекта, например:

```text
assets/history/apollo-11.jpg
```

---

## 5. Именование файлов

Имя файла должно быть:

- коротким;
- латиницей;
- в нижнем регистре;
- со словами через дефис.

Рекомендуемый шаблон:

```text
{тема}-{год}.{ext}
```

Примеры:

```text
apollo-11.jpg
gagarin-vostok.jpg
telstar-1962.jpg
phoenix-mars-launch-2007.webp
```

Не использовать:

- пробелы;
- кириллицу;
- длинные описательные фразы;
- случайные хеши вместо смысла.

---

## 6. Соответствие «файл ↔ событие»

Правило: **один файл изображения — одно событие**.

- один и тот же файл не переиспользуется для разных событий;
- одно событие не ссылается на несколько файлов через поле `image` (одно значение `image`);
- при замене изображения у события обновляется путь в `image` и при необходимости `imageAlt`.

---

## 7. Технические требования к файлу

| Параметр | Требование |
|----------|------------|
| Минимальная ширина | **1200 px** |
| Формат | **jpg** или **webp** |
| Расположение | `assets/history/` |
| Содержимое | узнаваемый, уместный кадр события; без лишнего текста и водяных знаков, если это возможно |

Высота не фиксируется жёстко, но кадр должен нормально обрезаться в карточке (`object-fit: cover`).

---

## 8. Alt-текст

Если у события указан `image`, поле `imageAlt` **обязательно**.

`imageAlt` должен:

- коротко и точно описывать, что видно на изображении;
- не дублировать `title` дословно;
- быть понятным без просмотра картинки;
- не содержать лишних оценок и рекламных формулировок.

Реплика или реконструкция допустима только если оригинального изображения нет; это нужно явно указать в `imageAlt`.

Пример:

```json
"imageAlt": "Старт ракеты Delta II с аппаратом Phoenix, 4 августа 2007"
```

---

## 9. Источник и лицензия

Для использования изображения нужны понятные права:

- Public Domain;
- подходящая Creative Commons;
- явное разрешение правообладателя;
- условия официального открытого архива, если они допускают использование.

Источник и лицензию **при необходимости** можно хранить отдельно в служебном файле:

```text
assets/history/library.json
```

Назначение `library.json`:

- служебный реестр метаданных изображений;
- поля вроде автора, лицензии, источника, URL оригинала, опциональной связи с `eventId`;
- **не runtime-файл** — приложение его не читает.

Привязка картинки к карточке для UI всегда идёт только через поля события `image` и `imageAlt`.

---

## 10. Краткий чеклист перед привязкой

1. Файл лежит в `assets/history/`.
2. Имя короткое, латиницей, через дефис.
3. Формат jpg или webp, ширина не меньше 1200 px.
4. Файл закреплён только за одним событием.
5. В событии заполнены `image` и `imageAlt`.
6. При необходимости метаданные происхождения добавлены в `library.json`.
7. Изображение читаемо в размере закрытой карточки.
8. Если исходник качественный — сначала пробовать `imagePosition`.
9. После смены главного события или изображения — Visual QA закрытой карточки.

---

## 11. Проверка

Перед добавлением изображения обязательно проверить:

- файл существует;
- путь `image` корректный;
- изображение загружается;
- `imageAlt` заполнен;
- отсутствует битая ссылка;
- карточка корректно отображается на desktop и mobile.

Существование файла и рабочий путь сами по себе недостаточны. После смены главного события или изображения обязателен Visual QA закрытой карточки (высота 210px, viewport 430×1100, `object-fit: cover`).

---

## 12. Visual QA закрытой карточки (главное событие)

Контекст проверки: закрытая карточка высотой **210px**, `.hist__image` с `object-fit: cover`, viewport **430×1100**.

Обязательные правила:

- существования файла и рабочего пути недостаточно;
- изображение должно быть читаемым в размере закрытой карточки;
- главный объект, лицо или сцена должны быть различимы;
- не использовать белые документы, перегруженные карты, мелкие объекты, низкоконтрастные или размытые кадры, если они не работают в карточке;
- если исходник качественный — сначала подобрать `imagePosition`;
- заменять исходник только если кадрирование не решает проблему;
- не подставлять изображение другого события;
- реплика или реконструкция допустима только если оригинала нет; это нужно явно указать в `imageAlt`;
- после смены главного события или изображения Visual QA закрытой карточки обязателен.
